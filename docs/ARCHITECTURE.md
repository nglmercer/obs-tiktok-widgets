# Architecture and ownership

The plugin lifecycle owns a single connection manager, a bounded dispatcher, a browser bridge, configuration, widgets, and the dock. One dedicated owner thread alone creates, connects, disconnects, and destroys the Rust C ABI client. No widget or JavaScript code can create a transport. The manager is the plugin's single owned instance; it deliberately has no process-global static destructor.

Commands are protected by a mutex and generation counter. Pending commands coalesce to the latest request. Username replacement first joins and destroys the old client. A superseded creation cannot attach to the new room. Reconnect replaces the single client; automatic retries are entirely Rust's existing reconnect implementation. Toggling reconnect applies to the next connection. Shutdown joins the owner before destroying callback userdata.

Native callbacks serialize FULL JSON while the borrowed event is valid, free it using ttl_string_free, and copy owned JSON into the queue. Unknown raw messages also preserve their retained bytes as base64. Exceptions are caught at every C callback boundary. Callbacks do not call Qt widgets, OBS or CEF and never destroy a client. Serialization/allocation are still work on the callback thread; oversized native inputs are additionally bounded by the upstream decoder.

The queue admits up to 2048 events, each at most 1 MiB serialized. Accepted events are FIFO. Its 8192-entry identity window deduplicates nonzero message IDs within room/method. Events without identity are never heuristically discarded. Queue-full and oversized events are rejected with counters shown in the dock. These are explicit loss conditions, not guaranteed delivery. Pending shutdown events are drained after callbacks stop, then any residual loss is counted.

The UI timer consumes up to 128 events with a five-millisecond between-event budget. Each event emits generic and typed DOM channels through nested obs_data_t objects using CallVendorRequest. Responses require status 100 and are freed through obs_websocket_request_response_free. A single vendor emission reaches Browser Source instances through OBS Browser's own broadcaster. No network server is involved.

Like aggregation and viewer coalescing happen in each built-in renderer, configured independently in milliseconds. This preserves every accepted source event on the global bus and avoids changing source FIFO. Gift totals are cumulative per user/gift/group; widgets replace the streak display rather than summing repeat totals.

Snapshots publish every two seconds. Unloaded sources cannot receive old DOM events; there is no historical chat/gift replay. A loaded source can synchronize connection state at its next snapshot. Source duplication shares a widget UUID; independent settings require **Duplicate widget**, which creates a new UUID. Widgets survive OBS restarts and live independently of scenes/profiles. OBS source references are retained/released within each libobs call.

Native transport configuration, event distribution, native UI, OBS source management, and web rendering are separate modules. Plugin configuration and widgets use atomic QSaveFile writes in OBS's module configuration directory. Settings are global to this plugin; profile and scene changes intentionally do not reconnect. Session bytes are transient in memory only, supplied by an external private file. Protect that file with OS permissions; the plugin never saves its path or contents. Cookie strings, signing source, or native error-detail strings never enter event payloads, URLs, or logs.
